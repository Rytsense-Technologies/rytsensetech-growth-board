Run a complete 360 SEO and AEO engagement. This is the full program: expect it
to take a while and produce roughly 30 deliverables.

# Step 0 — Intake

Read `input/site-profile.md` and `input/data-access.md`. If `$1` is supplied,
use it as the primary domain, overriding the profile.

**Validate before launching anything:**
- No primary domain → stop and ask. Nothing works without it.
- More than half of the profile is TBD → name the 5 TBDs that would most change
  the output and ask for those specifically. Do not demand the whole form.
- Check `data-access.md` and build the **activation list**: which agents run at
  full strength, which run degraded, which skip.

**Determine conditional activations** from the profile:

| Agent | Activates when |
|---|---|
| `local-seo-specialist` | physical locations or defined service areas |
| `international-seo-specialist` | more than one language or region |
| `ecommerce-seo-specialist` | ecommerce or marketplace business model |
| `programmatic-seo-engineer` | structured dataset with plausible query demand |
| `video-seo-specialist` | existing video, or video-dominant SERPs in the niche |
| `image-seo-specialist` | visual or product business, or image search traffic in GSC |
| `site-migration-specialist` | a migration is planned, or any agent proposes URL changes |
| `log-file-analyst` | server logs available |

State the activation list in chat before proceeding so the user can correct it.

# Step 1 — Recon (blocking)

Launch `seo-recon` alone. Everything depends on its inventory.

If recon cannot fetch the site at all, stop and report why. Do not let 48 agents
write reports about a site nobody has seen.

# Step 2 — Data foundation (parallel)

Launch together — these produce the evidence base every later agent reasons from,
so they run before anything analytical:
- `gsc-data-analyst`
- `ga4-data-analyst`
- `log-file-analyst` (if activated)
- `crawler-access-engineer`

Then launch `index-coverage-analyst`, which needs the GSC output.

**Checkpoint:** if neither GSC nor GA4 is available, say so plainly in chat
before continuing. The engagement is still worth running, but a large fraction
of it becomes professional inference rather than evidence, and the user should
know that before you spend their time.

# Step 3 — Technical audit (parallel)

- `technical-seo-engineer`
- `rendering-specialist`
- `site-architecture-specialist`
- `core-web-vitals-engineer`
- `mobile-seo-specialist`
- `international-seo-specialist` (if activated)

# Step 4 — Market intelligence (parallel, then sequential)

Parallel: `competitor-analyst`, `serp-landscape-analyst`, `brand-serp-specialist`

Then `keyword-strategist` (needs competitors and SERP landscape), then
`search-intent-analyst` and `topical-authority-strategist` in parallel.

# Step 5 — AEO department (parallel, then sequential)

Parallel: `aeo-strategist`, `entity-grounding-specialist`,
`conversational-query-researcher`

Then, sequentially: `ai-brand-monitor` (needs the prompt set), then
`answer-extractability-engineer` (needs the AEO strategy and rendering findings).

# Step 6 — Content strategy (sequential)

`content-architect` first — it depends on keywords, intent, topical authority,
competitors, and AEO.

Then in parallel: `content-refresh-specialist`, `content-pruning-specialist`,
`eeat-specialist`.

# Step 7 — Execution (parallel)

- `internal-linking-engineer`
- `schema-engineer`
- `authority-builder`
- `backlink-auditor`
- `digital-pr-specialist`
- `conversion-copywriter`

- `programmatic-seo-engineer` (if activated)
- `video-seo-specialist` (if activated)
- `image-seo-specialist` (if activated)

# Step 8 — Measurement (parallel)

- `seo-analyst`
- `conversion-analyst`
- `experiment-designer`
- `site-migration-specialist` (if any agent in steps 3-7 proposed URL changes)

# Step 8b — Opportunity discovery (sequential)

Launch `opportunity-finder`, then `opportunity-validator` on its register.

This runs late deliberately: it needs the GSC, GA4, SERP, competitor, and
conversion outputs to have something to mine. It answers a different question
from the rest of the engagement — not "how do we win the demand we serve" but
"what demand are we turning away". Skip it only if both GSC and GA4 are
unavailable, in which case say so rather than running it on nothing.

# Step 9 — Quality gate (blocking)

Launch `seo-qa-auditor` over everything in `output/`.

If the verdict is `BLOCK`, fix the blocking issues — re-running the specific
agent responsible — then re-run the auditor. Never present blocked work as
finished.

# Step 10 — Synthesis (sequential)

1. `seo-director` — strategy, conflict resolution, roadmap, kill list
2. `seo-forecaster` — models the roadmap the director actually chose
3. `seo-project-manager` — converts it into sprints and tickets

Then present in chat: the strategic thesis, the top 10 actions, the 30/60/90
plan, any validated business opportunities, what could not be determined and
why, and links to every deliverable.

# Orchestration rules

- **You own collection.** Never end your turn while agents are running. Wait for
  every agent in a wave, integrate, then start the next wave. A spawned task is
  not a completed task, and a completed agent whose parent has ended is wasted
  work.
- **Batch parallel launches in one message.** Agents in the same wave go in a
  single message with multiple tool calls, or they run sequentially and waste
  hours.
- **Pass context forward.** Each agent reads the `output/` files it needs. Tell
  it which ones in the prompt rather than making it search.
- **Enforce the no-fabrication rule.** If an agent returns confident numbers it
  had no way to obtain, send it back. This is the failure mode that matters most.
- **No live changes without sign-off.** Agents may draft and, where authorized in
  `data-access.md`, edit a repo. Nothing reaches a production site without
  explicit user approval.
- **Report honestly.** If agents produced thin output because access was missing,
  say that in the summary instead of padding it.
